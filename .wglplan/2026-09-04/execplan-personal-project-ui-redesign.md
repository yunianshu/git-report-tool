# 个人项目管理工作台与 UI 重设计 ExecPlan

> 创建时间：2026-09-04 12:04:51.890（Asia/Shanghai）
> 状态：已实施完成（2026-09-04）；验证记录见文末「实施验证记录」

## Goal

将当前“Git 报告 + OneDeploy 工具集合”重构为简洁、统一的个人项目管理桌面工具：

1. 以“项目”作为一等领域对象和全局上下文，项目可独立存在，不要求必须是 Git 仓库，也不要求必须配置部署。
2. 让 Git 活动、报告和部署成为项目的可选能力，而不是产品的信息架构中心。
3. 将 AI 助手提升为独立项目模块，可按需使用项目资料、Git 活动、报告摘要和部署状态，而不是只能生成 Git 报告。
4. 重建桌面端导航、工作台、项目页、AI 页、报告页、部署页和设置页的视觉层级与主要操作路径，做到“一页一个主要任务”。
5. 保留现有报告、AI 流式对话、部署、历史记录、密钥加密和 SSH 凭据加密能力，并兼容已有部署项目数据。

## Current-state Evidence

- `src/App.vue` 默认进入 `chat`，导航仅有“AI 助手 / 报告 / OneDeploy / 设置”，没有项目中心或工作台。
- `src/views/ChatView.vue` 的首要操作是选择日报/周报周期并执行“AI 生成报告”；`src/components/ChatPanel.vue` 的提示、快捷操作和上下文全部绑定报告。
- `src/utils/ai-context.js` 的系统提示词明确限定为“AI 报告助手”，唯一结构化上下文是 Git 提交。
- `src/store.js` 只有仓库、报告、聊天和部署状态，没有独立项目域或全局当前项目。
- `electron/deploy/deploy-projects.js` 已经保存了可复用的项目基础字段，但其模型和 IPC 被部署模块独占。
- `src/views/SettingsView.vue` 同时承担 Git 扫描、身份、AI 模型和仓库列表，信息密度过高且领域边界混乱。
- `src/views/DeployView.vue` 将项目配置、服务器凭据、部署选项、发布、日志和历史同时铺在一页，主操作不突出。
- `design/` 内现有设计稿仍使用“Git·报告 / 仓库扫描 / 报告生成”的旧信息架构，不能直接作为新定位的依据。
- 最近一次产品更名提交主要替换名称和文案，未改变上述领域模型、上下文或操作路径。

## Product and Design Decisions

### 信息架构

侧栏改为三组、六个入口：

- 工作区：`工作台`、`项目`
- 项目能力：`AI 助手`、`活动报告`、`部署`
- 系统：`设置`

应用顶部提供统一的当前项目选择器。切换项目后，AI、报告和部署自动使用同一项目上下文；选择“全部项目”时只允许适合聚合的工作台和报告能力，部署仍要求明确项目。

### 页面职责

- 工作台：展示真实项目数量、当前项目资料完整度、Git 活动状态、部署状态和最近操作；提供“创建项目 / 询问 AI / 生成报告 / 打开部署”的快捷入口，不编造指标。
- 项目：项目列表与项目详情；支持新建、编辑、归档/删除（删除沿用危险操作确认），字段只保留当前需要的名称、说明、本地目录、状态、标签和项目备注。
- AI 助手：独立对话工作区；明确显示当前项目，并允许勾选“项目资料 / Git 活动 / 报告摘要 / 部署状态”上下文来源；提供“项目总结 / 风险梳理 / 下一步计划 / 生成项目报告”等项目级快捷问题。
- 活动报告：保留现有周期、作者筛选、明细、统计和历史；增加当前项目/全部项目范围，明确标注“Git 活动是报告数据源之一”。非 Git 项目给出可理解的空状态，并引导使用 AI 基于项目资料整理报告。
- 部署：默认只展示当前项目的发布状态、环境、主要发布动作、阶段进度、日志和历史；服务器、健康检查、备份等低频配置收进“部署设置”面板，降低首屏复杂度。
- 设置：按“AI 服务 / Git 活动采集 / 个人身份 / 应用信息”分区；不再把已发现仓库表当作项目管理入口。

### 视觉系统

- 使用场景：约 1 米观看距离的桌面生产力工具，最小窗口保持现有 `1080 × 700`。
- 视觉温度：冷静、可靠、轻量，不做开发者霓虹风，也不使用装饰性插画。
- 色彩：保留现有青绿 `#0E7A6D` 作为唯一主强调色；白色主面、低饱和中性灰背景、语义色只用于状态。
- 排版：沿用跨平台中文系统字体以保证 Electron 离线可用性；标题通过字号、字重和留白建立层级，不新增远程字体依赖。
- 容器：减少“每块内容一个圆角卡片”的堆叠；主要页面使用页面标题、分区线、列表和少量有意义的状态面板。
- 动效：只保留视图切换、抽屉和状态变化所需的短过渡；遵守 `prefers-reduced-motion`。
- 可用性：正文不小于 14px，主要点击区域不小于 40px，键盘焦点可见，正文对比度达到 WCAG AA。

### 位置四问

| 页面 | 叙事角色 | 观众距离 | 视觉温度 | 容量策略 |
|---|---|---|---|---|
| 工作台 | 定向与概览 | 1 米桌面 | 安静、清晰 | 首屏只放真实状态与 4 个关键动作 |
| 项目 | 选择与维护 | 1 米桌面 | 稳定、直接 | 列表 + 单项目详情，编辑使用抽屉 |
| AI 助手 | 思考与协作 | 1 米桌面 | 专注、可信 | 对话为主，上下文来源为辅 |
| 活动报告 | 数据分析 | 1 米桌面 | 理性、克制 | 筛选固定、结果独立滚动 |
| 部署 | 高风险执行 | 1 米桌面 | 严谨、明确 | 发布动作居中，配置降级到面板 |
| 设置 | 低频配置 | 1 米桌面 | 中性、可扫描 | 分区导航，单区单职责 |

## Non-goals

- 本轮不新增任务看板、日历、工时、团队协作、云同步或账号系统。
- 不引入数据库、路由框架、状态管理框架或新的 UI 组件库。
- 不重写 Git 扫描、报告统计、AI 请求协议、SSH 发布和回滚底层逻辑。
- 不为缺失数据制造演示指标、虚假活动或虚假 AI 结论。
- 不执行 Git 提交、建分支或推送操作。

## Open Questions

以下采用默认答案即可直接执行；用户可在确认计划时覆盖：

1. “个人项目管理”默认解释为“个人开发项目工作台”，项目是报告、AI、部署等能力的容器；暂不加入通用待办/看板。默认：确认。
2. 保留现有青绿色视觉识别和 Element Plus，不另做三套风格方案；本次重点是信息架构与使用路径。默认：确认。
3. 现有 `deploy-projects.json` 继续作为兼容数据源，通过通用项目服务适配，不做破坏性文件迁移。默认：确认。

## Proposed Changes

### 1. 通用项目领域与兼容层

- 新增 `electron/project-service.js`
  - 在现有部署项目持久化之上提供通用项目 CRUD、规范化和脱敏接口。
  - 通用字段：`id`、`name`、`description`、`localPath`、`status`、`tags`、`notes`、`createdAt`、`updatedAt`。
  - 部署字段保持向后兼容；非部署项目允许 `targets` 为空或使用惰性默认值。
  - 不自动删除或搬迁用户已有数据文件。
- 调整 `electron/deploy/deploy-projects.js`
  - 复用项目服务的数据规范化/凭据处理，保留旧导出作为部署兼容适配器，避免双份项目数据。
- 调整 `electron/main.js`、`electron/preload.js`
  - 新增 `projects:list/save/remove` IPC。
  - 保留现有 `deploy:projects:*` IPC 兼容现有部署链路。
  - 将现有只点击 OneDeploy 的冒烟钩子改为覆盖新导航和默认工作台。

### 2. 前端状态与项目上下文

- 调整 `src/store.js`
  - 新增 `projects.items`、`projects.currentId`、`projects.loading`。
  - 提供当前项目派生数据所需的最小状态，避免每个页面各自维护项目选择。
- 新增 `src/composables/useProjects.js`
  - 集中加载、选择、保存和删除项目；统一错误处理和当前项目回退规则。
- 新增 `src/utils/project-context.js`
  - 将项目资料、匹配的 Git 活动、报告摘要和部署状态规范化为可展示/可传给 AI 的上下文片段。

### 3. 应用壳与共享组件

- 重写 `src/App.vue`
  - 默认进入工作台。
  - 使用分组导航、顶部当前项目选择器和一致的页面容器。
  - 统一加载项目与已有配置，保留进度/部署事件订阅。
- 新增 `src/components/AppSidebar.vue`
- 新增 `src/components/AppTopbar.vue`
- 新增 `src/components/PageHeader.vue`
- 新增 `src/components/EmptyState.vue`
  - 共享导航、页头、空状态和项目选择交互，避免视图重复。

### 4. 工作台与项目页

- 新增 `src/views/DashboardView.vue`
  - 基于真实项目、仓库、报告和部署历史生成概览与快捷入口。
- 新增 `src/views/ProjectsView.vue`
  - 项目列表、筛选、当前项目详情和空状态。
- 新增 `src/components/ProjectEditor.vue`
  - 新建/编辑抽屉，允许创建不含 Git、不含部署配置的普通项目。
  - 目录选择为可选操作；若目录是 Git 仓库则展示 Git 信息，但不改变项目成立条件。

### 5. AI 项目模块

- 重构 `src/views/ChatView.vue`
  - 移除首页式报告周期工具条，改为项目 AI 工作区。
  - 增加当前项目摘要、上下文来源选择和项目级快捷操作。
- 重构 `src/components/ChatPanel.vue`
  - 从“报告专用组件”改为接收通用上下文和快捷问题的对话组件。
  - 保留流式输出、停止、复制、保存和上下文预算控制。
- 重构 `src/utils/ai-context.js`
  - 系统角色改为个人项目助手。
  - 新增通用 `buildProjectContext`；Git 提交仅为可选分区。
  - 对项目备注、提交文本、历史报告和部署日志统一标记为不可信数据，保留提示注入防护和截断策略。

### 6. 报告与部署页面简化

- 调整 `src/views/ReportView.vue`、`src/utils/report-data.js`、`src/utils/report.js`
  - 支持按当前项目或全部项目收集与展示 Git 活动。
  - 更新标题、提示和空状态，避免把“仓库”当作用户的项目模型。
  - 保持现有日报/周报/双周报/月报、自定义周期、作者筛选、导出和历史能力。
- 重构 `src/views/DeployView.vue`
  - 以全局当前项目为输入，移除重复的部署项目选择器和顶栏 CRUD。
  - 将主要发布操作、阶段、日志和历史留在主页面。
- 新增 `src/components/deploy/DeployConfigDrawer.vue`
- 新增 `src/components/deploy/DeployRunPanel.vue`
- 新增 `src/components/deploy/DeployHistoryTable.vue`
  - 把大型部署视图拆分为单一职责组件；保存、测试连接、发布、取消和回滚行为保持不变。

### 7. 设置、样式、文案与文档

- 重构 `src/views/SettingsView.vue`
  - 按 AI 服务、Git 活动采集、个人身份、应用信息分区。
  - 已发现仓库只作为 Git 数据源状态，不再承担项目管理。
- 重写 `src/styles.css`
  - 建立颜色、间距、字号、边框、阴影和状态 token。
  - 重建应用壳、响应式布局、焦点态、减少动效支持；删除旧页面遗留和重复样式。
- 更新 `package.json`、`README.md`、`index.html` 和必要的构建元数据
  - 产品描述改为个人项目管理工作台。
  - 文档以项目、AI、活动报告、部署能力组织，明确 Git 是可选数据源。
- 更新或替换 `design/interface-mockups.html`
  - 保留为新信息架构的设计说明/对照稿，不再展示旧“Git·报告”导航。

## Step-by-step Implementation

1. 建立通用项目服务与 IPC 兼容层；用临时 Electron userData 隔离数据验证“旧部署项目可读、普通项目可存、凭据不下发”。
2. 建立前端项目状态/composable 和全局当前项目选择；验证跨视图切换不丢当前项目。
3. 重建应用壳、工作台和项目页，先形成可运行的结构版（Junior pass），用真实空状态和现有本地数据展示，不制造演示数据。
4. 在结构版检查点截图 1440×900 与 1080×700，核对导航层级、首屏容量、溢出和主要动作；如信息架构需偏离本计划，先更新计划并再次确认。
5. 泛化 AI 上下文与聊天组件，接入项目资料、Git 活动、报告和部署四类可选来源；验证无 Git 项目也能正常对话。
6. 将报告页改为项目范围，并保留现有报告能力与历史数据格式。
7. 拆分并简化部署页，把低频配置收进抽屉；验证发布前确认、运行进度、取消、历史和回滚入口没有丢失。
8. 重构设置页与全局样式，统一文案和空状态；扫描 UI 文案中残留的错误“Git 工具”定位。
9. 更新产品说明和设计稿；清除仅用于本次验证的截图、冒烟日志及其他临时文件，保留业务所需发布日志。
10. 运行完整构建、隔离数据测试、Electron 冒烟和真实点击验证；对照验收标准逐项审计。

## Tests & Acceptance Criteria

### A. 产品定位与导航

- [ ] 应用默认打开“工作台”，一级导航完整显示工作台、项目、AI 助手、活动报告、部署、设置。
- [ ] 除“Git 活动/数据源”等必要语境外，Logo、导航、页标题、空状态和产品说明不再把产品称为 Git 管理或 Git 报告工具。
- [ ] 当前项目在顶栏统一选择，切换后 AI、报告、部署使用相同项目；视图切换不重置选择。

验证：Electron 启动截图、逐入口点击、文本扫描。

### B. 非 Git 项目成立

- [ ] 可以只填写项目名称创建项目，不要求 `.git`、Compose、服务器或 API Key。
- [ ] 项目资料可编辑并持久化；重启应用后仍存在。
- [ ] 现有部署项目可出现在项目列表中，原部署目标与凭据配置仍可使用，渲染层拿不到明文凭据。

验证：使用临时 userData 的创建/重启测试、旧格式 fixture 兼容测试、IPC 返回值检查。

### C. AI 服务整个项目

- [ ] AI 页面不再要求先选择报告周期或先扫描 Git 仓库。
- [ ] 用户可独立启用/禁用项目资料、Git 活动、报告摘要、部署状态上下文，并能看到当前附带内容的摘要/规模。
- [ ] 无 Git 数据时仍可基于项目说明和备注对话；无任何项目时提供清晰引导而非报错。
- [ ] 系统提示词定位为项目助手，所有外部上下文按不可信数据处理并受字符预算限制。
- [ ] 流式输出、停止、复制、保存、错误提示继续可用。

验证：上下文构建隔离测试、无 Git/有 Git 两种真实场景点击测试、AI 接口使用现有配置的可选联调。

### D. 报告与部署能力不回退

- [ ] 报告仍支持 5 种周期、作者范围、明细、统计、历史、复制和 Markdown 导出。
- [ ] 当前项目范围只收集匹配项目的 Git 数据；全部项目范围保持聚合能力；非 Git 项目显示明确空状态。
- [ ] 部署页仍支持项目配置、多个部署目标、版本识别、连接测试、发布确认、8 阶段进度、取消、日志、发布历史和回滚。
- [ ] 部署低频配置不占据默认首屏，主要发布动作在 1080×700 下无需横向滚动即可到达。

验证：报告 fixture/真实仓库场景、部署配置隔离测试、Electron UI 点击测试；不对真实生产服务器执行发布。

### E. 视觉与可用性

- [ ] 1440×900、1280×800、1080×700 三种窗口下没有页面级横向滚动、主要操作遮挡或文本重叠。
- [ ] 正文至少 14px，主要点击区域至少 40px，键盘焦点清晰，正文对比度达到 WCAG AA。
- [ ] 空项目、无 Git、无报告、未配置 AI、未配置部署五类空状态均有单一明确下一步。
- [ ] 控制台无新增 error/warning；所有一级导航、项目切换、项目编辑、AI 上下文开关、报告切换、部署设置抽屉可点击。

验证：Electron/Playwright 截图与点击脚本、控制台采集、人工视觉检查。

### F. 工程质量

- [ ] `npm run build:renderer` 通过。
- [ ] `npm run build` 或与本机平台相符的打包前构建链路通过；若完整安装包耗时过长，至少验证 Electron 生产模式加载 `dist`。
- [ ] 项目、AI 上下文、部署展示组件职责清晰，不把新逻辑继续堆入现有 800+ 行视图。
- [ ] 不新增未使用依赖，不保留调试日志、冒烟日志或临时截图。

## Risks & Rollback

1. **项目模型与部署模型冲突**
   - 风险：错误迁移会导致部署配置或加密凭据丢失。
   - 控制：不移动/删除现有数据文件；项目服务作为兼容层；所有数据验证使用临时 userData fixture；保存时保留未知字段和原加密字节。
   - 回滚：恢复项目服务/IPC/前端调用，原 `deploy-projects.json` 仍可由旧代码读取。

2. **AI 上下文膨胀或提示注入**
   - 风险：四类上下文叠加超预算，或项目备注/日志内含恶意指令。
   - 控制：分区预算、行边界截断、明确不可信分隔符、默认只附带当前项目资料。
