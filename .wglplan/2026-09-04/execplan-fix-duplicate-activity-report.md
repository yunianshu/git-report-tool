# 修复活动报告重复数据 ExecPlan

> 创建时间：2026-09-04 18:16:16.921（Asia/Shanghai）
> 状态：已实施完成（2026-09-04 18:24:14.413）；原计划与标题栏新增范围均已确认

## Goal

修复“活动报告点击生成后提交数据成倍重复”的根因，确保扫描根目录数量、仓库发现事件、提交收集结果和报告统计在并发预热/手动扫描场景下保持一致且不重复。

同时按用户新增要求精简全局标题栏：删除“数据仅保存在本机”和“新建项目”，新建项目仅保留在工作台与项目页，消除重复入口。

## Current-state Evidence

- 当前本机配置只有 2 个扫描根目录：`D:\AndroidProjectNet`、`D:\AiProject`。
- 对这两个根目录执行单次真实扫描，结果为 75 个唯一 Git 仓库。
- 按应用实际时序并发调用普通缓存扫描与 `force=true` 强制扫描后：两个扫描各返回 75 个仓库，共广播 150 次仓库发现事件；75 个路径全部各出现 2 次。
- 最新历史报告显示“Git 活动源：150 个”，报告包含 74 条提交，但只有 37 条唯一提交文案，37 组均恰好重复 2 次。
- 根因位于 `electron/git-service.js` 的 `scanReposCached`：`force=true` 会同时绕过已完成缓存和 `scanInflight`，因此配置保存触发的后台预热尚未结束时，设置页立即强制扫描会对相同参数启动第二次扫描，并广播第二套相同事件。
- `src/views/SettingsView.vue` 对仓库发现事件直接 `push`，没有按规范化路径去重；`collectCommits` 也直接信任传入仓库列表，导致重复路径被重复执行 `git log` 并合并进报告。
- 工作区已有用户未提交修改：`src/App.vue`、`src/composables/useProjects.js`、`src/views/SettingsView.vue`。实现时仅对设置页仓库事件处理做最小增量修改，保留其余现有改动。

## Non-goals

- 不删除或改写已有历史报告、配置、项目数据和用户目录。
- 不改变扫描根目录、排除规则、报告周期、作者过滤、历史保存和导出格式。
- 不通过报告文案、提交标题关键字或单案例条件做去重。
- 不执行 Git 提交、建分支、推送或代码回滚。
- 不引入新依赖或新的状态管理方案。
- 不删除工作台、项目页和空状态中的新建/创建项目入口。

## Open Questions

无阻塞问题。默认保留已有重复历史报告，因为自动删除或改写用户数据属于破坏性操作；修复只保证后续扫描和报告不再产生重复数据。

## Proposed Changes

### 1. `electron/git-service.js`

- 调整扫描缓存并发语义：相同 `roots + excludes` 已有扫描进行中时，无论后续调用是否 `force=true`，均复用当前扫描 Promise；`force` 只绕过已完成缓存，不再绕过同参数进行中任务。
- 对 `collectCommits` 的仓库输入按跨平台规范化路径稳定去重，保留首次出现顺序，避免任何上层重复路径造成重复 Git 查询与重复报告数据。
- 同步代码注释，使缓存和强制扫描语义与实际实现一致。

### 2. `src/views/SettingsView.vue`

- 仓库发现事件进入共享状态前使用现有 `pathKey` 做路径去重；重复事件不再创建表格行，也不进入仓库信息加载队列。
- 保留当前文件中“扫描后提示加入项目”的用户未提交修改，不重写相关逻辑。

### 3. `scripts/git-service-selftest.cjs`

- 新增隔离自测，使用系统临时目录创建真实 Git 仓库与足够目录以触发扫描让步/并发窗口。
- 覆盖普通扫描与强制扫描并发时同一仓库只广播一次。
- 覆盖重复仓库路径传入提交收集时，每个真实 commit 只返回一次。
- 测试结束清理临时目录；不读写正式应用配置与历史数据。

### 4. 标题栏精简（实施中新增范围）

- 调整 `src/components/AppTopbar.vue`：删除“数据仅保存在本机”和“新建项目”操作区，并删除不再使用的 `create-project` 事件声明。
- 调整 `src/App.vue`：删除 `AppTopbar` 上不再存在的 `create-project` 事件监听；保留工作台、项目页现有创建入口与 `openProjectEditor` 链路。
- 调整 `src/styles.css`：删除仅服务于已移除标题栏内容的 `.topbar-actions`、`.data-note` 样式，保持标题栏项目选择器与窗口控制按钮布局。

## Step-by-step Implementation

1. 在 Git 服务中先修正相同扫描签名的进行中去重顺序，并更新语义注释。
2. 在提交收集入口集中规范化并稳定去重仓库路径，确保所有调用方都受保护。
3. 在设置页流式仓库事件入口增加路径幂等判断，避免共享状态和信息加载队列被污染。
4. 新增真实 Git fixture 自测，复现并锁定“预热 + 强制扫描并发”和“重复输入收集”两条链路。
5. 运行自测、渲染构建，并再次使用当前两个真实根目录执行并发扫描验证事件数等于唯一仓库数。
6. 检查 `git diff`，确认只包含计划内最小改动且没有覆盖工作区原有用户修改；检查并清理本次测试临时日志/目录。
7. 删除标题栏本机数据提示和新建项目入口，移除关联的无效事件与专用样式；重新构建并核对工作台、项目页创建入口仍可用。

## Risks & Rollback

1. **强制扫描语义变化**
   - 风险：用户在同参数扫描尚未完成时再次点击扫描，将复用正在进行的最新扫描，而不是并发再启动一遍。
   - 控制：进行中的扫描本身正在读取当前磁盘状态；并发再扫没有有效的新鲜度收益，反而污染全局事件流。首次任务完成后再次点击仍会由 `force=true` 正常绕过已完成缓存。
   - 回滚：仅恢复 `scanReposCached` 的判断顺序。

2. **路径去重误合并**
   - 风险：Windows 下仅大小写或斜杠不同的两个字符串会被视为同一路径。
   - 控制：这与现有扫描 `visited` 的 Windows 规范化语义一致；稳定保留首次路径供展示和 Git 调用。
   - 回滚：移除提交收集入口的规范化集合，保留扫描并发修复。

3. **工作区已有修改冲突**
   - 风险：设置页存在未提交改动。
   - 控制：只在既有 `onScanRepoFound` 回调内追加幂等判断，使用文件当前版本作为补丁基线；完成后逐行审查 diff。
   - 回滚：只撤销本计划新增的判断行，不使用 `git reset --hard` 或整文件覆盖。

4. **历史重复数据**
   - 风险：旧报告仍显示重复，这是历史文件原有内容。
   - 控制：本计划不自动改写历史；如用户后续要求清理，将单独列出影响范围并按危险操作确认机制执行。

5. **标题栏入口移除**
   - 风险：用户在 AI、报告、部署或设置页无法直接从顶栏创建项目。
   - 控制：这是用户明确要求的去重；工作台和项目页仍保留创建入口，顶栏继续保留全局项目选择与窗口控制。
   - 回滚：恢复 `AppTopbar` 操作区、事件声明、`App.vue` 监听与对应两条样式。
