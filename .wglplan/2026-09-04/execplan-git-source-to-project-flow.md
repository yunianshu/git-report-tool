# Git 活动源逐项转换为项目 ExecPlan

> 创建时间：2026-09-04 18:32:55.828（Asia/Shanghai）
> 状态：已实现并验证（2026-09-04）；验收记录见文末

## Goal

建立清晰、显式的 Git 活动源转换流程：用户在工作台点击“Git 活动源”后进入活动源列表，再对单个仓库点击“转换为项目”；转换完成后该子项立即显示已转换状态，且不会重复创建同目录项目。

## Current-state Evidence

- `src/views/DashboardView.vue` 已展示“Git 活动源”数量，但使用静态 `div`，没有点击行为。
- `src/views/SettingsView.vue` 的“Git 活动”分区已经包含仓库表格和单项“加为项目”能力，但列表位于扫描根目录、排除目录之后，不能作为工作台指标的直接落点。
- `src/composables/useProjects.js` 与 `src/App.vue` 仍会在预热扫描后弹出一次性“全部加为项目”提示；`SettingsView` 扫描完成后也会触发同一批量提示。这与用户要求的“进入列表后逐项转换”冲突。
- `src/utils/path.js` 已提供 `pathKey`，现有列表使用它判断仓库是否已经成为项目，可直接复用并避免大小写/分隔符差异导致重复展示。
- `src/App.vue` 当前直接将子页面的 `navigate` 事件赋给 `view`，还不能表达“进入设置页并指定 Git 活动分区”的二级导航意图。
- 当前工作区只有既有无关未跟踪内容 `.spec-workflow/`、`_verify-icon.cjs`；本功能实现不会修改或提交它们。

## Product Decisions

- “Git 活动源”入口指工作台概览指标；点击后复用现有“设置 → Git 活动”页面，不新增第七个一级导航或第二套仓库列表。
- Git 活动分区把活动源列表放在首位，扫描根目录与排除规则作为下方配置，进入后无需先越过配置区才能看到子项。
- 删除自动批量导入提示，转换只由列表中的单项按钮触发；按钮文案统一为“转换为项目”，完成后显示“已转换”。
- 工作台指标始终显示，包括零项目场景，使“扫描到仓库但尚无项目”时仍能从工作台进入转换流程。

## Non-goals

- 不新增独立侧栏菜单、路由框架、状态管理库或后端数据表。
- 不支持一键全部转换、批量选择、撤销转换或自动删除原 Git 仓库。
- 不改变项目模型、项目删除流程、Git 扫描算法、报告生成和部署行为。
- 不清理既有配置中的 `repoImportPrompted` 字段；停止读取和写入后保留该未知字段，以兼容旧数据并避免破坏性迁移。
- 不修改或提交 `.spec-workflow/`、`_verify-icon.cjs`。

## Open Questions

无阻塞问题。默认将“点击子项转换”实现为每行明确的“转换为项目”操作按钮，不把整行变成无提示的创建操作，避免用户浏览列表时误触。

## Proposed Changes

### 1. `src/views/DashboardView.vue`

- 将“Git 活动源”指标改为可访问的按钮，点击发出 `activity-sources` 导航意图。
- 将概览指标移出“已有项目”条件，使零项目但已有扫描源时也能进入列表。
- 保持其余指标和工作台内容的数据来源不变。

### 2. `src/App.vue`

- 新增集中导航函数，将 `activity-sources` 映射为设置页并指定 `git` 初始分区；其他一级页面仍保持原导航语义。
- `SettingsView` 接收目标分区；侧栏继续高亮“设置”，不增加伪一级页面。
- 删除应用启动预热后的自动批量项目导入提示。

### 3. `src/views/SettingsView.vue`

- 增加受约束的 `initialSection` 属性，进入活动源流程时直接激活 `git` 分区。
- 将 Git 活动源列表移动到 Git 分区首位，并把“加为项目”统一改为“转换为项目”、“已加入”改为“已转换”。
- 转换按钮增加单项进行中状态与防重复点击；保存成功后复用现有项目加载逻辑刷新状态。
- 删除扫描完成后的自动批量转换提示，保留手动重新扫描及根目录变更后的扫描行为。

### 4. `src/composables/useProjects.js`

- 删除不再使用的 `promptImportDiscoveredRepos`、批量转换逻辑及其专用依赖。
- 保留项目加载、选择、保存、删除的单一职责 API。

### 5. `src/styles.css`

- 为可点击概览指标补充按钮重置、悬停、键盘焦点和箭头/交互反馈样式。
- 保持四列/两列响应式布局与现有视觉系统一致，不引入新设计 token。

## Step-by-step Implementation

1. 删除自动批量导入项目调用和 composable 中对应实现，确保扫描只发现活动源，不擅自创建项目。
2. 在应用壳建立 `activity-sources → settings/git` 的集中导航映射，并让设置页接收初始分区。
3. 将工作台 Git 活动源指标改为按钮并移到项目条件之外，覆盖有项目和零项目场景。
4. 调整设置页 Git 分区内容顺序、转换文案和单项进行中保护，复用 `pathKey + projectsSave + loadProjects` 完成转换。
5. 补齐交互指标的焦点/悬停样式，并审查最小窗口响应式布局。
6. 运行项目服务自测、前端生产构建和 Electron 隔离冒烟；使用本机真实扫描数据或等价隔离状态验证入口、列表、单项转换和已转换状态。
7. 审查差异与未跟踪文件，更新本 ExecPlan 验收记录；按 `AGENTS.md` 主动生成 Conventional Commit 并推送当前分支。

## Risks & Rollback

1. **设置页二级导航状态错误**
   - 风险：从工作台进入后仍落到默认 AI 分区，或侧栏高亮异常。
   - 控制：导航意图在 `App.vue` 单点映射，设置页属性只接受现有四个分区值，侧栏实际 view 始终为 `settings`。
   - 回滚：恢复直接 `view = $event`，工作台指标退回静态展示。

2. **重复创建项目**
   - 风险：快速双击或路径格式差异创建多个相同目录项目。
   - 控制：转换前使用 `pathKey` 二次检查，转换中按路径锁定按钮，成功后立即刷新项目集合。
   - 回滚：移除新入口，保留设置页原有单项操作。

3. **移除自动批量提示改变既有体验**
   - 风险：首次扫描不再主动询问一次性导入。
   - 控制：这是本需求明确选择的显式逐项转换流程；工作台入口长期可见，不依赖一次性提示。
   - 回滚：恢复 `promptImportDiscoveredRepos` 调用与实现。

4. **设置页内容重排影响最小窗口**
   - 风险：1080×700 下活动源表格或下方扫描配置空间不足。
   - 控制：列表沿用现有 flex 自适应表格，配置区保持可滚动页面结构；使用最小窗口冒烟核对。

5. **代码回滚方式**
   - 不使用 `git reset --hard`，只按文件恢复本计划新增的导航、按钮、文案和样式；不删除用户项目或仓库数据。
