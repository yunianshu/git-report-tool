# Spec：部署设置支持复制其他项目的部署配置

## 背景与目标

用户为新项目配置部署时，服务器地址、部署目录、健康检查、数据同步等与已有项目高度雷同，
目前需逐项手动输入。本功能支持在「部署设置」抽屉里从其他项目整套复制部署配置，
凭据（SSH 密码/私钥口令、数据同步导入密码）一并复制，无需重输。

## 业务规则

### R1 复制范围
- 必须复制：部署形态（deployMode/composeFile/scriptMode 全部子项）、版本策略（version.strategy/manual）、部署选项（deploy 全部子项）、全部部署目标 targets（含服务器、凭据、部署目录、健康检查、数据同步及其凭据）。
- 禁止复制：项目名称、本地目录、描述、标签、备注、状态、debugMode 等项目自身属性。
- 验收：[源项目 A 已完整配置，目标项目 B 仅填名称] → [在 B 的部署设置中复制 A 后，B 的部署形态/版本策略/部署选项与 A 一致，B 的目标列表 = 原有目标 + A 的全部目标（含各环境服务器与健康检查配置）]

### R2 凭据随复制
- SSH 密码、私钥口令、数据同步导入密码必须随配置一起复制（主进程内复制加密凭据，明文不出主进程）。
- 验收：[A 的某环境用密码认证且已存密码] → [复制到 B 后，B 对应环境密码框显示已保存掩码，且「测试连接」能凭该密码成功连接]

### R3 追加不覆盖
- 源项目的目标必须追加到当前项目目标列表末尾，当前项目已有目标禁止被删除或修改。
- 每个复制的目标必须生成新的目标 id，避免与现有目标 id 冲突。
- 验收：[B 已有 1 个环境，A 有 2 个环境] → [复制后 B 有 3 个环境，原环境配置不变]

### R4 入口与确认
- 入口在「部署设置」抽屉内；源项目下拉不得包含当前项目自身。
- 执行前必须弹确认框，明确告知复制范围与"当前未保存的修改将丢弃"。
- 验收：[打开 B 的部署设置] → [能看到复制入口；下拉仅列出其他项目；确认框说明后果后才会执行]

### R5 复制后状态同步
- 复制成功后，部署页表单必须刷新为复制后的最新配置（含新目标），当前选中目标切到新追加的第一个目标；连接测试结果清空。
- 验收：[复制成功] → [部署设置抽屉内可见 A 的环境与配置；主界面部署目标下拉含新环境]

### R6 新建项目默认带入配置
- 首次为某项目保存部署配置（deploy-projects 中尚无该项目）时，必须自动从"最近更新且至少配置过一个服务器主机"的其他项目整套复制部署配置（复制规则同 R1-R3），追加到项目默认环境之后。
- 不存在满足条件的源项目时静默跳过，不报错。
- 复制成功后必须向用户提示来源项目与带入的环境数量。
- 验收：[已有已配置项目 A（2 个环境），新建项目 B 首次保存部署配置] → [B 的部署形态/版本策略/部署选项与 A 一致，环境 = B 默认环境 + A 的 2 个环境（凭据可用），并提示已带入；后续再次保存 B 不重复带入]

### R7 发布页快速添加新版本
- 发布卡必须提供「新版本」入口：点击后输入新版本号，确认即把版本策略切换为"手动指定"、保存配置，发布按钮立即显示新版本，无需进入部署设置。
- 发布进行中禁止触发该入口；版本号不能为空。
- 验收：[当前手动版本 0.1.2] → [发布卡点「新版本」输入 0.1.3] → [发布按钮显示"🚀 发布 0.1.3"，配置已持久化]

## 职责边界（不做什么）

- 不做"仅复制单个环境"（本期只做整套复制）。
- 不做部署配置导出/导入文件。
- 不做复制后自动保存表单其他未保存修改；未保存修改一律丢弃并事先告知。
- 不修改凭据加密方案与存储结构。
