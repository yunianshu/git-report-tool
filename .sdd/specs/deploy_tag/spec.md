# 部署版本标签与更新范围

本次沿用现有部署、历史和更新说明模块，合并记录设计与验收，不扩展文档体系。

- 部署及数据同步全部成功 → 在采集时的提交创建 v版本号，本地历史保存标签；失败、取消、回滚不打标。
- 同一项目和目标再次部署 → 以上次成功记录的提交为稳定起点，标签用于标识版本，列出范围内全部提交；历史缺失继续兼容最近标签及首次发布最近 60 条。
- 同名标签同提交 → 复用；不同提交 → 保留旧标签并记录告警，不改变真实部署成功状态。
- 更新说明继续使用现有本地整理及 AI 总结。自动推送被部署仓库标签、未提交内容追踪和成品包溯源不在本次范围。

实现：release-notes 固定范围终点、隔离目标、校验标签解引用后的提交；deploy-service 在数据同步成功之后、历史落盘之前等待创建标签。

验证：扩展现有真实临时 Git 自测，以模拟传输运行真实部署编排，覆盖连续发布、冲突、取消、回滚、失败不打标及超过 60 条提交；运行部署相关自测与渲染构建。真实服务器部署未执行。

验证结果：更新内容专项自测通过；通用部署自测 50 项通过（Windows 下使用 Git Bash，避免 WSL 错误解释盘符路径）；数据同步专项 10 组通过；Vite 渲染构建通过。
