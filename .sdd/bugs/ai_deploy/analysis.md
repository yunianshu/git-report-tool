# AI 部署助手审核修复

## 已复现的根因

- 文件写入仅检查字符串前缀，Windows junction 可让目标落到项目外；临时夹具实际写出了文件。
- 本地 Compose / 脚本原文进入诊断和文件生成提示词；虚构 Token 在请求内容中完整出现。
- 混合 share 与 upload 的目录清单套用时直接取第一项，选中了运行时输出而非种子数据。
- AI 合并重建 blockers 时丢掉版本、服务器地址和部署路径；空缺项清单使未就绪项目变为 ready。
- Vue 组件的结果未绑定项目/环境，确认后读取可变 props，旧结果及迟到响应可作用于新上下文。

## 修复与验收

- 按真实项目根逐段 lstat，读写拒绝链接；覆盖备份采用独立 UUID 并排他创建。
- 两条 AI 请求路径统一清理常见凭据字面量，包括变量默认值、多行私钥与认证参数；保留安全参考。
- 同步目录保留用途，仅允许一个明确上传项；多个或未知项原子拒绝，配置不发生部分写入。
- 根据最终部署形态、版本策略、本地文件和远程检查证据重算就绪状态；前置条件只允许补充。
- Vue 同步监听上下文变更，清空结果；请求与确认框绑定上下文代次，拒绝迟到结果。

## 验证方式

- `node scripts/deploy-ai-selftest.cjs`：真实临时文件与配置，SSH/AI 打桩；覆盖越界写入、备份、提示词虚构秘密、空 AI 清单、形态切换与混合同步。
- `node scripts/deploy-ai-context-selftest.cjs`：编译真实 Vue 组件并通过自定义 renderer 挂载，验证 watch、异步顺序、切换后的确认框和正常套用；IPC/确认框打桩。
- 真实生产服务器不参与测试，不进行部署或数据同步。

## 验证结果

- AI 后端回归、Vue 上下文隔离、数据同步专项（10 组）、部署基础（50 项）通过。
- 前端生产构建通过；语法检查通过。
- 部署基础测试首次误用系统 WSL Bash，Windows 文件路径无法解析；仅为测试进程把 Git Bash 放入 PATH 后通过，未修改系统环境或测试断言。
